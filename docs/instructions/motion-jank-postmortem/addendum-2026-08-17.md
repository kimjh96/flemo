# Addendum — 2026-08-17 evening: live attribution re-verification and refuted defaults

Steady-60 desktop player routing (PR #261) shipped and was feel-tested the same day in plen, the real consumer app with a fully loaded infinite member list. Findings, in order:

1. **Pop unfreeze stall: reachable and fixed.** Each heavy-list pop began with a 50–66ms frame gap. The settle gate's wave detector keys on ADDED nodes, but the returning screen reuses frozen DOM; wall-clock give-up timers therefore released directly into the unfreeze style/layout block. Give-up releases now require two consecutive fast frames (`animStartAnchor.ts`). Hold-aware remeasurement found a 17.7ms maximum post-release gap, no 30ms+ gaps, and blocks absorbed into the hold.
2. **Desktop always-snap default refuted on the player.** The pop parallax's long subpixel tail felt like ratcheting ("드르륵") under always-snap's integer holds-and-steps. The default reverted to the velocity gate, consistent with the original same-display verdict: fractional glide wins for slow tracked motion.
3. **Residual attributed to the macOS Chrome present pipeline, re-verified live.** The residual remained perceptible after frame timing and value generation were clean. The falsification triangle closed: compiled, player+always, player+gate, and the historical no-`<script>` pure-CSS control all exhibited it; Safari and old Android Chrome on a Note 9 did not. Forcing continuous present immediately smoothed it, confirmed by the user ("매끄럽긴 합니다", meaning "It is smooth").

## Instrumentation notes for the next round

- `--show-fps-counter` was not confirmed effective on Chrome 151: a fresh-profile instance showed no visible HUD, and the user felt no change. That instance also had a cold GPU-pipeline profile, creating a double confound; see the cold-cache section. The reliable present-forcing switch at the time was the DevTools "Frame Rate" HUD, enabled remotely through CDP (`DOM.enable` → `Overlay.enable` → `Overlay.setShowFPSCounter {show:true}`) and held on by a persistent session.
- Never use a fresh-profile browser instance for a user jank verdict. Cold Graphite/Dawn pipeline caches cause real first-transition stalls that can resemble the bug under investigation.
- The @flemo/devtools transition recorder (PR #263) segments frame gaps into hold/released phases. Measurements that ignore the hold phase misattribute absorbed blocks as running jank; this occurred in-session.
